## 新增 / Added

- 无线连接：手机扫码即可配对（Android 系统识别的 `WIFI:T:ADB;S:<名称>;P:<密码>;;` 二维码），也支持“配对码”路径，配对端口与连接端口分开校验。/ Wireless connection: pair by scanning an Android-recognised `WIFI:T:ADB;S:<name>;P:<password>;;` QR code, with a pairing-code fallback that validates the pairing and connection ports separately.
- 通过 mDNS 自动发现手机当前的连接端口；已配对设备会被记录（可删除），下次默认进入“连接已配对设备”。/ Discovers the phone's current connection port over mDNS and remembers paired devices (removable), so the next session defaults to “connect a paired device”.
- 未自动发现时的兜底：网页二维码获取手机 IP 并给出打开开发者选项 / 无线调试 / 读取端口的分步指引，或手动填写 IP 与端口。/ Fallbacks when discovery fails: a web QR code that reveals the phone IP with step-by-step instructions for Developer options, Wireless debugging and the port, or manual IP and port entry.
- 无线失败原因分类与可操作提示（未扫码超时、未发现设备、网络不可达、端口被拒、配对码错误、未授权、ADB 服务缺少局域网权限），并可单独断开某个无线 transport。/ Actionable, classified wireless failures (scan timeout, device not found, unreachable network, refused port, wrong code, unauthorized, ADB server without LAN access) plus per-transport wireless disconnect.
- 用户显式确认后可重启 ADB 服务（先停止本应用的投屏）；macOS 包声明 `NSLocalNetworkUsageDescription` 与 `NSBonjourServices`。/ An explicit, confirmed ADB server restart (mirrors started by this app are stopped first); the macOS bundle declares `NSLocalNetworkUsageDescription` and `NSBonjourServices`.
- 每设备“锁定捕获方向”（scrcpy `--capture-orientation=@值`，0 / 90 / 180 / 270）：画面保持正向，手机物理旋转不再带动投屏窗口；修改只重启该设备。/ Per-device locked capture orientation (scrcpy `--capture-orientation=@value`, 0 / 90 / 180 / 270) keeps content upright and stops the mirrored window from following the phone's physical rotation; changing it restarts only that device.

## 修复 / Fixed

- macOS：主窗口在前台时恢复 Dock 图标与系统菜单栏（激活策略在 Regular / Accessory 之间切换），收起到托盘后恢复为后台代理。/ macOS: the Dock icon and menu bar return while the main window is in front (activation policy switches between Regular and Accessory) and revert to accessory when hidden to the tray.
- macOS 通知按连接分线程，多设备不再折叠成一条，并附上默认提示音。/ macOS notifications use one thread per connection, so multiple devices no longer collapse into a single group, and they play the default sound.
- 无线配对不再“无反应”：ADB 服务的 mDNS 发现失效时（常见于旧构建或其他工具遗留的陈旧服务），约 10 秒内在详情行给出原因与处理建议，“重启 ADB 服务”按钮常驻可见，重启后自动重新生成二维码并继续等待扫描。/ Wireless pairing no longer looks dead: when the ADB server's mDNS browsing is broken (typically a stale server left by an older build or another tool), the dialog explains it after about ten seconds, keeps the restart button reachable at all times, and resumes scanning with a fresh QR code after a restart.
- 无线流程写入应用日志（各阶段、退出码与 ADB 输出，配对码脱敏）；上一步仍在进行时点击“确认并连接”会给出可见提示而不是静默返回；二维码生成异常也会显示在状态行。/ Wireless phases, exit codes and ADB output are logged with the pairing code masked; clicking “confirm and connect” while a step is still running now shows a visible message instead of returning silently, and QR generation errors surface in the status line.
- 补上一条此前漏译的无线错误文案（en / fr / de / ja）。/ Translated a wireless error message that was missing from the catalog (en / fr / de / ja).

## 变更 / Changed

- 无线连接入口精简为“首次配对”（二维码 / 配对码）与“连接已配对设备”（mDNS / 手动 IP + 端口）两类，其余模式移除。/ Wireless entry points were reduced to “first-time pairing” (QR code or pairing code) and “connect a paired device” (mDNS or manual IP and port); other modes were removed.
- 实机取证结论：ADB 的 user-rotation 锁定会被 OEM 忽略，且无法注入传感器数据，因此横屏需求由 `--capture-orientation` 在投屏侧解决，不做手机侧自动化。/ Verified on real devices: ADB user-rotation locks are ignored by the OEM and sensor data cannot be injected, so landscape needs are solved on the capture side via `--capture-orientation` instead of automating the phone.
